Chapitre 1 · Séquence 1

Représentation de l’information et architecture

Prends le temps de comprendre les définitions, les unités, les règles et les exemples. Chaque partie s’ouvre pour afficher les explications.

Une base b indique combien de symboles différents sont disponibles. Les chiffres autorisés vont de 0 à b − 1. Dans un système positionnel, la valeur d’un chiffre dépend de sa position : rang 0 à droite, puis rang 1, rang 2, etc.

  • Base 2 — binaire : 0 et 1. Un chiffre binaire est un bit.
  • Base 8 — octal : chiffres de 0 à 7.
  • Base 10 — décimal : chiffres de 0 à 9.
  • Base 16 — hexadécimal : chiffres 0 à 9 et lettres A à F, avec A=10, B=11, C=12, D=13, E=14, F=15.

Exemple 1 : décomposer un nombre décimal

(2538)₁₀ = 2×10³ + 5×10² + 3×10¹ + 8×10⁰
= 2000 + 500 + 30 + 8

Exemple 2 : binaire vers décimal

(10110)₂ = 1×2⁴ + 0×2³ + 1×2² + 1×2¹ + 0×2⁰
= 16 + 4 + 2 = (22)₁₀

Attention : le chiffre 8 est interdit en base 8 ; les lettres A à F ne sont utilisées qu’en hexadécimal.

Un ordinateur manipule de l’information sous forme de bits. Un bit (contraction de « binary digit ») est la plus petite unité d’information utilisée ici : il vaut soit 0, soit 1. Un bit peut représenter deux états, par exemple éteint/allumé ou faux/vrai.

Un octet est un groupe de 8 bits. Par exemple, 01000001 contient 8 bits et forme donc un octet. Avec 8 bits, on peut former 2⁸ = 256 combinaisons différentes, de 00000000 à 11111111. En non signé, ces combinaisons représentent les valeurs de 0 à 255.

Ne pas confondre les unités

  • b minuscule signifie bit ; B majuscule signifie octet.
  • 1 octet = 8 bits ; donc 4 octets = 32 bits.
  • Dans les unités décimales courantes : 1 ko = 1 000 octets, 1 Mo = 1 000 ko et 1 Go = 1 000 Mo.
  • En convention binaire, on rencontre aussi 1 Kio = 1 024 octets, 1 Mio = 1 024 Kio et 1 Gio = 1 024 Mio.

Exemple 1 : convertir des octets en bits

5 octets × 8 = 40 bits

Exemple 2 : combien d’octets pour 64 bits ?

64 ÷ 8 = 8 octets

Exemple 3 : nombre de combinaisons

Avec n bits, on peut représenter 2ⁿ combinaisons. Ainsi, 4 bits donnent 2⁴ = 16 combinaisons ; 8 bits donnent 2⁸ = 256 combinaisons.

Attention : le nombre de combinaisons n’est pas toujours égal à la plus grande valeur signée. Sur 8 bits non signés, on va de 0 à 255 ; sur 8 bits en complément à 2, on va de −128 à +127.

Multiplie chaque chiffre par la puissance de la base correspondant à son rang, puis additionne. À gauche de la virgule, les puissances commencent à 0 et augmentent vers la gauche.

Exemple 1 : binaire vers décimal

(101101)₂ = 1×2⁵ + 0×2⁴ + 1×2³ + 1×2² + 0×2¹ + 1×2⁰
= 32 + 8 + 4 + 1 = (45)₁₀

Exemple 2 : octal vers décimal

(7513)₈ = 7×8³ + 5×8² + 1×8¹ + 3×8⁰
= 3584 + 320 + 8 + 3 = (3915)₁₀

Exemple 3 : nombre binaire à virgule

(10110,011)₂ = 1×2⁴ + 1×2² + 1×2¹ + 1×2⁻² + 1×2⁻³
= 16 + 4 + 2 + 0,25 + 0,125 = (22,375)₁₀

Après la virgule, les rangs sont négatifs : 2⁻¹=0,5 ; 2⁻²=0,25 ; 2⁻³=0,125.

Pour la partie entière, divise successivement par la base cible. Note les restes, puis lis-les de bas en haut. Pour une fraction, multiplie successivement la partie fractionnaire par la base cible et note les parties entières dans l’ordre.

Exemple : convertir 45 en binaire

45 ÷ 2 = 22 reste 1
22 ÷ 2 = 11 reste 0
11 ÷ 2 = 5 reste 1
5 ÷ 2 = 2 reste 1
2 ÷ 2 = 1 reste 0
1 ÷ 2 = 0 reste 1
Lecture de bas en haut : (101101)₂

Exemple : convertir 0,625 en binaire

0,625×2=1,25 → bit 1, reste 0,25
0,25×2=0,5 → bit 0, reste 0,5
0,5×2=1,0 → bit 1, reste 0
Donc (0,625)₁₀=(0,101)₂

Exemple complet

(58,625)₁₀ = (111010,101)₂

Comme 8=2³, un chiffre octal correspond à 3 bits. Comme 16=2⁴, un chiffre hexadécimal correspond à 4 bits. Pour compléter un groupe, ajoute des zéros à gauche pour la partie entière.

Binaire vers octal

1101011₂ → 001 101 011
001=1, 101=5, 011=3
Donc (1101011)₂=(153)₈

Binaire vers hexadécimal

11110110₂ → 1111 0110
1111=F et 0110=6
Donc (11110110)₂=(F6)₁₆

Hexadécimal vers octal

(F65)₁₆ → 1111 0110 0101₂
→ 111 101 100 101₂ → (7545)₈

5.1 Pourquoi faut-il représenter les nombres à virgule ?

Les nombres entiers sont faciles à écrire en binaire, mais un ordinateur doit aussi représenter des nombres comme 12,5 ; 0,75 ; 0,003 ou 1250000,25. Il faut donc coder la partie située avant la virgule et celle située après la virgule.

En base 2, les poids à gauche de la virgule sont 2⁰, 2¹, 2², etc. Les poids à droite sont 2⁻¹, 2⁻², 2⁻³, etc. Autrement dit, ils valent 1/2, 1/4, 1/8, 1/16…

Exemple 1 : lire un nombre binaire à virgule

(10,101)₂ = 1×2¹ + 0×2⁰ + 1×2⁻¹ + 0×2⁻² + 1×2⁻³
= 2 + 0,5 + 0 + 0,125
= (2,625)₁₀

Exemple 2 : convertir un décimal en binaire

On sépare la partie entière et la partie fractionnaire, puis on les convertit indépendamment.

12₁₀ = 1100₂
0,5 × 2 = 1,0 → premier bit : 1
Donc 0,5₁₀ = 0,1₂
Finalement : (12,5)₁₀ = (1100,1)₂

5.2 Représentation en virgule fixe

En virgule fixe, on décide à l’avance combien de bits sont réservés à la partie entière et combien à la partie fractionnaire. La virgule ne se déplace pas : sa position est implicite et reste toujours la même.

Exemple : si le format prévoit 4 bits pour la partie entière et 4 bits pour la fraction, le mot 0011 1000 peut être interprété comme 0011,1000₂, soit 3 + 1/2 = 3,5. Ce format est simple, mais il limite à la fois l’amplitude du nombre et la précision disponible.

Si on réserve peu de bits à la partie entière, les très grands nombres ne peuvent pas être représentés. Si on réserve peu de bits à la fraction, les petites variations décimales sont mal représentées.

5.3 Représentation en virgule flottante : l’idée

La virgule flottante permet de représenter des nombres très grands ou très petits en utilisant une forme analogue à l’écriture scientifique. En base 10, on écrit par exemple :

45000 = 4,5 × 10⁴
0,00072 = 7,2 × 10⁻⁴
−325000 = −3,25 × 10⁵

On sépare donc le nombre en trois idées : le signe (positif ou négatif), la significande (les chiffres qui portent la précision) et l’exposant (qui indique où placer la virgule). En base 2, on utilise une puissance de 2 à la place d’une puissance de 10.

5.4 Exemple de virgule flottante en base 2

Prenons le nombre binaire 1101,01₂. On déplace la virgule vers la gauche jusqu’à obtenir un seul chiffre non nul à sa gauche. On compense ce déplacement par une puissance de 2 :

1101,01₂ = 1,10101₂ × 2³

Le nombre n’a pas changé : 1,10101₂ vaut 1 + 1/2 + 0/4 + 1/8 + 0/16 + 1/32, et multiplier par 2³ revient à déplacer la virgule de trois rangs vers la droite. Le nombre 2,5₂, par exemple, s’écrit 1,01₂ × 2¹.

5.5 Normalisation et limites

Pour les nombres binaires normalisés non nuls, on écrit généralement la valeur sous la forme 1,xxxxx₂ × 2ᵉ. Le premier chiffre avant la virgule est alors 1. Cette écriture rend les nombres plus cohérents et permet d’utiliser efficacement les bits de précision.

Tous les nombres décimaux ne possèdent pas une écriture binaire finie. Par exemple, 0,1 en base 10 donne une suite binaire périodique. Comme le nombre de bits disponibles est limité, l’ordinateur conserve une approximation : de petits écarts d’arrondi peuvent donc apparaître dans les calculs.

5.6 Ensuite : le format IEEE 754

IEEE 754 est une norme qui précise comment coder les nombres en virgule flottante. En simple précision, le mot contient 32 bits répartis en trois champs :

1 bit de signe | 8 bits d’exposant | 23 bits de fraction
  • Signe S : 0 pour un nombre positif ou nul, 1 pour un nombre négatif.
  • Exposant E : exposant auquel on ajoute un biais de 127 pour le stocker dans le format normalisé.
  • Fraction F : bits qui suivent le 1 implicite de la significande normalisée. Pour un nombre normalisé, la significande est de la forme 1,F.

Exemple IEEE 754 : coder 12,5

On commence par les étapes générales de la virgule flottante, puis on les applique au format normalisé IEEE 754.

1) Conversion : 12,5₁₀ = 1100,1₂
2) Normalisation : 1100,1₂ = 1,1001₂ × 2³
3) Signe : S = 0
4) Exposant réel : 3 ; exposant codé : 3 + 127 = 130 = 10000010₂
5) Fraction : 10010000000000000000000 (on omet le 1 initial implicite)
6) Mot final : 0 | 10000010 | 10010000000000000000000

Il faut bien distinguer l’exposant réel 3 de l’exposant stocké 130. Le biais 127 est ajouté uniquement pour coder l’exposant dans le champ de 8 bits. Les exposants tout à 0 ou tout à 1 sont réservés à des cas particuliers (zéro, nombres subnormaux, infinis et NaN).

6.1 Pourquoi faut-il une représentation des nombres signés ?

Un mot binaire non signé de n bits représente uniquement des valeurs positives ou nulles. Avec 8 bits, par exemple, il va de 0 à 255. Pour représenter des valeurs négatives comme −5 ou −128, il faut convenir d’une règle d’interprétation des bits. Les mêmes bits peuvent donc désigner des valeurs différentes selon la représentation utilisée.

Dans les exemples ci-dessous, on travaille sur 8 bits. Le nombre de bits doit toujours être précisé, car on ne code pas −13 de la même manière sur 8 bits et sur 16 bits.

6.2 Représentation signe et valeur absolue (SVA)

Le bit le plus à gauche est le bit de signe : 0 signifie positif et 1 signifie négatif. Les autres bits donnent la valeur absolue du nombre en binaire.

+13 : 0 | 0001101 → 00001101
−13 : 1 | 0001101 → 10001101

Pour décoder 10001101, le premier bit indique « négatif » ; les 7 autres bits 0001101 valent 13. Le résultat est donc −13.

Limite : cette méthode possède deux représentations du zéro : 00000000 pour +0 et 10000000 pour −0. Sur 8 bits, la plage est de −127 à +127.

6.3 Complément à 1 (C1)

Pour obtenir la représentation d’un nombre négatif en complément à 1, on écrit d’abord sa valeur positive sur le nombre de bits demandé, puis on inverse chacun des bits : chaque 0 devient 1 et chaque 1 devient 0.

+13 sur 8 bits : 00001101
Inversion de tous les bits : 11110010
Donc −13 en C1 : 11110010

Pour retrouver la valeur d’un mot négatif en C1, on inverse ses bits pour retrouver la valeur absolue, puis on met le signe négatif. Ainsi, 11110010 → inversion → 00001101 = 13, donc −13.

Le C1 possède lui aussi deux zéros : 00000000 (+0) et 11111111 (−0). Sur 8 bits, sa plage est également de −127 à +127.

6.4 Complément à 2 (C2)

Pour former un nombre négatif en C2, deux méthodes équivalentes existent : inverser tous les bits du nombre positif puis ajouter 1, ou calculer le complément à 1 puis ajouter 1. Le C2 est la représentation la plus courante pour les entiers signés dans les ordinateurs.

Étape 1 — +13 : 00001101
Étape 2 — inversion : 11110010
Étape 3 — ajouter 1 : 11110010 + 1 = 11110011
Donc −13 en C2 sur 8 bits : 11110011

Pour décoder un mot C2 dont le bit de gauche vaut 1, on peut inverser les bits, ajouter 1 et mettre un signe moins. Exemple : 11110011 → inversion 00001100 → +1 donne 00001101 = 13, donc la valeur est −13.

6.5 Comment reconnaître et décoder un mot C2 ?

  • Si le bit de gauche est 0, le nombre est positif ou nul : convertis normalement en décimal.
  • Si le bit de gauche est 1, le nombre est négatif : inverse les bits, ajoute 1, convertis le résultat en décimal et ajoute le signe −.

Exemple : 11111011 commence par 1. Inversion : 00000100. Ajouter 1 : 00000101, soit 5. Le mot vaut donc −5 en C2.

6.6 Plages de valeurs selon le nombre de bits

Pour n bits, les intervalles sont différents selon la représentation :

Non signé : 0 à 2ⁿ − 1
Signe et valeur absolue : −(2ⁿ⁻¹−1) à +(2ⁿ⁻¹−1)
Complément à 1 : −(2ⁿ⁻¹−1) à +(2ⁿ⁻¹−1)
Complément à 2 : −2ⁿ⁻¹ à +(2ⁿ⁻¹−1)
Sur 8 bits non signés : 0 à 255
Sur 8 bits signés SVA ou C1 : −127 à +127
Sur 8 bits C2 : −128 à +127
Sur 16 bits C2 : −32768 à +32767

Le C2 gagne une valeur négative supplémentaire, car il n’a qu’une seule représentation du zéro.

6.7 Débordement (overflow) : attention

Sur 8 bits en C2, le maximum positif est +127. Si un calcul dépasse cette plage, le résultat binaire peut sembler valide mais sa valeur signée devient incorrecte : c’est un débordement.

Exemple : 127 + 1
01111111 + 00000001 = 10000000
Interprété en C2 sur 8 bits, 10000000 vaut −128 : le résultat ne représente donc pas +128.

À retenir : précise toujours la représentation et la taille du mot ; pour coder un négatif en C2, complète à la largeur demandée avant d’inverser et d’ajouter 1.

Exemple de simplification

A + A · B = A

Si A = 1, la sortie est déjà 1. Si A = 0, le terme A·B vaut aussi 0 : dans les deux cas, le résultat est A.

Les théorèmes de De Morgan permettent de transformer une somme logique en produit logique et un produit logique en somme logique, en complémentant chaque variable.

¬(A + B) = Ā · B̄
¬(A · B) = Ā + B̄

Pour plusieurs variables, la même règle s’étend à toutes les entrées : le complément d’un OU devient un ET des compléments ; le complément d’un ET devient un OU des compléments.

Exemple

¬(A + B + C) = Ā · B̄ · C̄
¬(A · B · C) = Ā + B̄ + C̄

Méthode : déplacer la barre sur l’expression, remplacer OU par ET (ou ET par OU), puis complémenter chacune des variables.

Chapitre 4 · Séquence 4

Simplification des fonctions logiques combinatoires

Cours détaillé fondé sur le PDF de la Séquence 4 : représentations, formes canoniques, algèbre de Boole et tableaux de Karnaugh.

La simplification consiste à transformer une expression logique en une expression équivalente comportant moins de termes ou de variables. Le but est de faciliter la lecture et de réduire le nombre de portes logiques nécessaires au montage.

Le cours présente deux méthodes : la méthode algébrique, qui applique les lois de l’algèbre de Boole, et la méthode graphique de Karnaugh, qui permet de regrouper les combinaisons voisines de façon systématique.

Petit exemple de l’intérêt de simplifier

Les expressions A + AB et A décrivent exactement la même fonction. La première comporte deux termes, alors que la seconde n’en comporte qu’un. On peut donc utiliser la forme simplifiée A dans le circuit.

Une fonction logique combinatoire peut être représentée de quatre façons complémentaires :

  • Table de vérité : liste toutes les combinaisons d’entrées et la valeur de sortie correspondante.
  • Forme algébrique : exprime la sortie à l’aide des opérateurs NON, ET et OU.
  • Logigramme : représente les portes logiques et leurs connexions.
  • Tableau de Karnaugh : range les valeurs de sortie dans une grille conçue pour simplifier l’expression.

Avec n entrées binaires, la table de vérité contient 2ⁿ lignes. Par exemple, trois entrées A, B et C donnent 2³=8 combinaisons.

Exemple avec trois entrées

Pour A=0, B=1, C=0, la combinaison d’entrée est 010. La table de vérité indique si la sortie vaut 0 ou 1 pour cette combinaison. Cette même ligne peut ensuite être traduite en terme algébrique ou reportée dans une case de Karnaugh.

Une expression est dite canonique lorsque chacun de ses termes contient toutes les variables de la fonction.

Première forme canonique — somme de produits : on additionne les mintermes des lignes où la sortie vaut 1. Dans un minterme, une variable qui vaut 1 reste directe et une variable qui vaut 0 est complémentée.

Deuxième forme canonique — produit de sommes : on multiplie les maxtermes des lignes où la sortie vaut 0. Dans un maxterme, une variable qui vaut 0 reste directe et une variable qui vaut 1 est complémentée.

Construire un minterme

Pour la combinaison A=0, B=1, C=0, le minterme est A̅BC̅. Pour construire le maxterme associé à cette même combinaison, on écrit (A+B̅+C).

La notation numérique R(0,3,4,6,7) désigne la somme des mintermes numérotés 0, 3, 4, 6 et 7. La notation I(1,2,5) désigne le produit des maxtermes des lignes 1, 2 et 5.

La méthode algébrique cherche les variables communes, met en facteur les termes et supprime les parties redondantes. Il est utile d’écrire une transformation par ligne et de nommer la propriété utilisée.

PropriétéIdentité
IdentitéA+0=A ; A·1=A
ComplémentaritéA+A̅=1 ; A·A̅=0
IdempotenceA+A=A ; A·A=A
AbsorptionA+AB=A ; A(A+B)=A

Exemple détaillé : A + AB

1. Mettre A en facteur : A+AB=A(1+B).

2. Comme 1+B=1, on obtient A·1.

3. Par la propriété d’identité, A·1=A.

Résultat : A+AB=A.

Deuxième exemple : (A+B)(A+C)

Développer : (A+B)(A+C)=AA+AC+AB+BC. Comme AA=A, on a A+AC+AB+BC. Par absorption, A+AC=A et A+AB=A ; il reste A+BC.

Attention aux barres de complément : elles portent parfois sur une variable, parfois sur une parenthèse entière. Il faut les conserver exactement avant d’appliquer les règles.

Le tableau de Karnaugh est une grille où chaque case correspond à une combinaison de la table de vérité. L’ordre des lignes et colonnes suit le code Gray : 00, 01, 11, 10. Deux cases voisines ne diffèrent que par une seule variable.

  1. Construire la grille correspondant au nombre de variables.
  2. Reporter dans chaque case la valeur de la sortie.
  3. Repérer les 1 et les regrouper en blocs de 1, 2, 4, 8… cases.
  4. Faire les groupes les plus grands possibles ; les groupes doivent être rectangulaires ou carrés.
  5. Les bords opposés sont adjacents et un 1 peut appartenir à plusieurs groupes.
  6. Pour chaque groupe, conserver uniquement les variables qui ne changent pas d’état, puis faire le OU des termes obtenus.

Exemple de regroupement de deux cases

Supposons que deux cases adjacentes correspondent aux termes AB̅C et ABC. La variable B change (0 puis 1), tandis que A=1 et C=1 restent constants. Le groupe donne donc AC : B disparaît.

Un groupe de 4 cases élimine deux variables ; un groupe de 8 cases élimine trois variables. Ne jamais regrouper des cases en diagonale ni former des groupes de 3 ou de 5 cases.

  • Utilise la méthode algébrique lorsque des facteurs ou des identités évidentes apparaissent.
  • Utilise Karnaugh pour simplifier méthodiquement une fonction définie par une table ou des mintermes.
  • Vérifie que l’expression simplifiée donne la même sortie pour les combinaisons d’entrée.
  • À partir de l’expression finale, dessine le logigramme en remplaçant chaque opération par la porte correspondante.

Le TD4 reprend ces compétences : simplification algébrique, lecture et simplification de cartes de Karnaugh, puis table de vérité et réalisation logique d’un système de contrôle qualité.

Pour calculer A − B sur un nombre fixé de bits, on remplace la soustraction par A + C2(B). Le complément à 2 de B se trouve en deux étapes :

ASCII : code alphanumérique historique sur 7 bits, donc 128 combinaisons. Il est souvent stocké sur un octet, dont le huitième bit peut servir de bit de parité.

Avec une parité paire, on choisit le bit de parité pour que le nombre total de bits à 1 soit pair. Avec une parité impaire, il doit être impair. Cette méthode détecte certaines erreurs, mais pas toutes (par exemple, un nombre pair de bits inversés peut passer inaperçu).

Exemple du cours : virgule ASCII 0101100 contient 3 bits à 1.

Lettre D : 1000100 contient 2 bits à 1 → parité paire 01000100.

CRC (contrôle de redondance cyclique) : on représente les bits par un polynôme P(x), on ajoute m zéros où m est le degré du générateur G(x), puis on effectue une division modulo 2 (soustractions remplacées par XOR). Le reste de m bits est le CRC et remplace les zéros ajoutés. À la réception, on divise le message reçu par G(x) : un reste non nul signale une erreur détectée.

Exemple du cours : G(x)=x²+x+1, donc G=111. Pour les données 110111, le reste est 11 ; le message transmis est 11011111.

CRC pas à pas avec les données 110111

  1. Le générateur est G=111, de degré 2 : il faut donc ajouter deux zéros aux données.
  2. Les données 110111 deviennent 11011100.
  3. On effectue la division modulo 2 par 111. En modulo 2, la soustraction est remplacée par XOR : 1 XOR 1=0 et 1 XOR 0=1.
  4. Le reste obtenu a au plus deux bits : ici 11.
  5. On remplace les deux zéros ajoutés par le reste : le message transmis est 11011111.
  6. À la réception, on divise le message reçu par 111. Un reste nul signifie qu’aucune erreur n’a été détectée par ce contrôle ; un reste non nul indique une erreur détectée.

Limite importante : un CRC ne permet pas de corriger ou de retrouver automatiquement les bits originaux ; il signale seulement certaines erreurs de transmission.

Unités utilisées dans le cours : 1 octet = 8 bits ; 1 Ko = 1024 octets ; 1 Mo = 1024 Ko ; 1 Go = 1024 Mo.
